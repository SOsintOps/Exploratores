About the Toolkit & Its Name

Why is the toolkit named "Exploratores"?

"Exploratores" were the scouts or reconnaissance units in the Roman army, tasked with gathering intelligence about the terrain, enemy movements, and local resources ahead of the main legionary force. This toolkit is named in their spirit, aiming to provide modern digital "scouts" (OSINT practitioners) with the tools to explore the digital landscape and gather information effectively.

Who were the "Exploratores" historically?

In ancient Rome, "Exploratores" were soldiers specifically chosen for their skills in reconnaissance, observation, and survival. They often operated in small groups, deep in potentially hostile territory, to provide crucial intelligence for military commanders, enabling informed strategic decisions. Their role was vital for the safety and success of military campaigns.

What is the main purpose of the Exploratores OSINT Toolkit?

The Exploratores OSINT Toolkit aims to consolidate and organize a wide range of OSINT (Open Source Intelligence) tools and resources to facilitate investigation and information gathering activities. It provides a centralized access point and a consistent structure for these tools.

Are there any guarantees regarding the accuracy or reliability of the tools and results?

No guarantees are provided regarding the accuracy, completeness, reliability, or timeliness of the information obtained through the tools accessible via the toolkit. Each external tool has its own terms of service and limitations. The analyst is fully responsible for independently verifying and validating all collected information before using it for any purpose.

Am I responsible for validating information found using the toolkit?

Yes, absolutely. The Exploratores OSINT Toolkit provides access to various tools and external resources. However, any information, data, or "news" obtained through these tools must be critically evaluated and independently validated by you, the analyst, before being considered reliable or actionable. The toolkit itself does not verify the accuracy or truthfulness of the data retrieved from external sources.

Learning Resources on OSINT

Where can I find resources to learn more about OSINT?

There are numerous high-quality resources for learning OSINT. For a structured and in-depth approach, Michael Bazzell's books (such as "Open Source Intelligence Techniques" and "Extreme Privacy") are considered reference texts in the field and are highly recommended. Another valuable text, although more focused on Deep and Dark Web investigations but with relevant OSINT principles, is "Deep Dive: A Forensics Handbook for Deep Web and Dark Web Investigations." In addition to books, it is useful to follow specialized blogs, participate in webinars, and join professional OSINT communities to stay updated on the latest techniques and tools.

Functionality & Customization

Do I need to install additional software to use the toolkit?

No, the toolkit consists of HTML, CSS, and JavaScript pages that run directly in a modern web browser. No specific client-side software installation is required, apart from the browser itself. Linked external tools may have their own requirements.

Are my search activities tracked by the toolkit?

The Exploratores toolkit itself (the local HTML/CSS/JS files or those served internally) does not implement mechanisms for tracking or logging your specific queries or activities. However, it is crucial to remember that each external service or website you access through the toolkit's links operates under its own privacy policies and may log your interactions. Always use safe and aware Browse practices.

Is it necessary to create dedicated investigative accounts for using some of these tools?

Yes, for many OSINT activities, especially when interacting with social media platforms or other online services, it is highly recommended and often essential to use dedicated, non-attributable "investigative" or "sock puppet" accounts. Using personal accounts can compromise your investigation, expose your identity or organization, and may violate the terms of service of some platforms. Always ensure your investigative accounts are managed securely and ethically.

Can the Exploratores OSINT Toolkit pages be customized?

Yes, the Exploratores Toolkit pages are designed to be customizable. You can add new tools, modify existing categories, or adapt functionalities. For a detailed guide on how to do this, please refer to the How to Customize Pages page.

LLMs and Toolkit Development

How can I create a new page or add features using a prompt for an LLM (like this AI Assistant)?

To interact effectively with a Large Language Model (LLM) for developing pages or features for this toolkit, it's advisable to provide a clear and detailed prompt. Key elements to include are:

  • Clear Objective: Precisely describe what the new page or feature should do. For example, "I want a page for looking up IP addresses that queries three specific services."
  • Desired HTML Structure: If you have an idea of how elements should be organized (e.g., number of input fields, labels, buttons, sections), specify it.
  • JavaScript Logic: Explain the expected behavior. For example, "When the user enters an IP and clicks button X, open this specific URL, inserting the encoded IP at point Y in the URL."
  • Specific Texts: Provide the exact text for titles, labels, input placeholders, button text, user notes, etc.
  • Reference to Project Guidelines: It is crucial to remind the LLM to strictly adhere to the "HTML Coding Standards," "CSS Guidelines," "JavaScript Guidelines," and stylistic directives defined for the Exploratores project.
  • Specific Request Example: "Create a page named 'IPLookup.html' for the Exploratores toolkit. It should have an input field with id 'ipAddressInput' and placeholder 'Enter IP Address'. Add three buttons: 'Search ServiceA', 'Search ServiceB', 'Search ServiceC'. JavaScript functions should be named 'IPLookup_SearchServiceA', etc., use the provided input, validate and encode it before opening the respective service URL in a new tab. The page must follow the entire standard Exploratores structure (navbar, footer, etc.)."

The more detailed and compliant with project conventions your prompt is, the better the result generated by the LLM will be.

Can you provide an example prompt for an LLM to create a basic Exploratores page template from scratch?

Certainly. Here's an example prompt you could adapt to ask an LLM to generate a new page template:

"Please generate the complete HTML code for a new page named 'ExampleTool.html' for the Exploratores OSINT Toolkit.
The page should be in English and strictly follow all established project guidelines:
1. Standard DOCTYPE and HTML structure (`<html lang="en">`).
2. `<head>`: UTF-8 charset, viewport meta, title 'Example Tool • Exploratores', link to 'IBM Plex Sans' font, and a link to `../assets/css/style.css`.
3. `<body>`: Standard Exploratores `<nav>` bar (ensure 'ExampleTool.html' is not active in the main menu structure, perhaps make a relevant 'Tools' submenu item active if applicable, or no item active if it's a standalone new tool page not yet in the menu), a `<main>` section, and the standard `<footer>`.
4. `<main>`: Start with `<h1 class="page-title">Example Tool</h1>`. Then, include a basic `<section class="search-instructions">` containing a label for 'exampleInput', a `div.input-container` with an `<input type="text" id="exampleInput" class="input-field" placeholder="Enter example data">`. Below this, add a `div.button-grid` with one button: `<button type="button" class="button" onclick="ExampleTool_DoSomething()">Run Example</button>`.
5. `<footer>`: `<p>Global Security Italy • Rome (IT) <a href="license.html">License</a></p>`.
6. `<script>`: Place before `</body>`. Include only the standard Exploratores navbar submenu JavaScript. Define an empty JavaScript function `function ExampleTool_DoSomething() { /* TODO: Implement */ }`.
Ensure no inline styles or superfluous comments are added to the code. The structure should be clean and ready for further content addition."

Remember to replace placeholders like 'ExampleTool.html' and provide more specific details about actual inputs, buttons, and JavaScript logic when creating real tools.
