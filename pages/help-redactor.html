What Redactor does

Redactor removes personally identifiable information (PII) from text and CSV files. It is designed to be used before sending documents to AI models, or any third party where the original data must not be shared.

How it works: Redactor scans your input, a text or a CSV file, replaces each piece of sensitive data with a coded placeholder such as [EMAIL_1] or [IBAN_2], and keeps a session map that links each placeholder back to its original value. You can later restore the original data by pasting the output back into the Restore section.

Privacy note: all processing happens inside your browser. No data is sent to any server.

TEXT MODE

Redacting a text

Use this to remove PII from a block of plain text.

  1. Make sure the Text button is selected at the top of the Redactor section. It is selected by default.
  2. Paste your text into the Input text box.
  3. Click Redact. A redacted version appears in the Redacted text box below.
  4. Click Copy to Clipboard to copy the result and paste it where needed.

Each piece of PII is replaced by a bracketed placeholder. The same value always receives the same placeholder within a session, so if the same email address appears five times, all five instances become [EMAIL_1].

RESTORE — TEXT MODE

Restore a redacted Text

Use this after you receive a text response from an AI model (or any other tool) that contains placeholders.

  1. Make sure the Text button is selected at the top of the Restore section. It is selected by default.
  2. Copy the text you need to restore that contains placeholders, for example the AI response.
  3. Paste it into the Restore box.
  4. Click Restore. Every placeholder is replaced with its original value.
  5. Click Copy to Clipboard to copy the restored text.

CSV MODE

Redacting a CSV file

Use this to remove PII from an entire CSV file and download the cleaned version.

  1. Click the CSV button at the top of the Redactor section.
  2. Click Browse... and select your CSV file.
  3. Click Redact CSV. A summary shows how many rows were processed and how many cells were redacted.
  4. Click Download Redacted CSV to save the cleaned file as redacted.csv. The file is saved to your browser's default download folder.

NOTE: The CSV parser follows the RFC 4180 standard and handles quoted fields, embedded commas, and line breaks inside cells.

RESTORE — CSV MODE

Restoring a CSV file

Use this to restore an entire CSV file that was previously redacted. This is the correct way to reverse a Redact CSV operation — do not paste CSV content into the text restore box.

  1. Click the CSV button at the top of the Restore section.
  2. Click Browse... and select the redacted CSV file (the one downloaded after using Redact CSV).
  3. Click Restore CSV. The tool applies the session map to every cell in the file. A summary shows how many rows were processed and how many cells were restored.
  4. Click Download Restored CSV to save the file as restored.csv in your browser's default download folder, with all original values reinstated.

Important: both Restore modes work only within the same browser session. If you close or refresh the tab, the map is lost. To carry a session across tabs or days, use Copy Map (JSON) and Import Map — both are described in the Redaction Map section below.

CUSTOM PATTERNS

How to add a custom pattern

If you need to redact data that Redactor does not detect automatically, you can add your own patterns using regular expressions.

In the following example the analyst added the regular expression to detect the NIR (Numéro d'Inscription au Répertoire).

To do that, the analyst followed this procedure:

  1. Type name: enter a short label for your pattern, for example NIR_FR. Use only letters, digits, and underscores.
  2. Regex: enter your regular expression without surrounding slashes. Example: [12]\d{2}[ ]?(?:0[1-9]|1[0-2]|20)[ ]?\d{2}[ ]?\d{3}[ ]?\d{3}[ ]?\d{2} matches NIR (Numéro d'Inscription au Répertoire).
  3. Colour: choose a colour for the badge shown in the Redaction Map.
  4. Case-insensitive: tick this box if the pattern should match regardless of capitalisation.
  5. Click Add Pattern. The pattern is saved in your browser's local storage and will be available the next time you open the page.

To remove a custom pattern, click the Remove button next to it in the table. Built-in patterns cannot be removed.

REDACTION MAP

Redaction Map

The Redaction Map shows every placeholder created in the current session, its data type, and the original value it replaced.

  • Copy Map (JSON): copies the full map as a JSON object. Paste this somewhere safe if you want to restore data in a future session.
  • Import Map: paste a previously exported JSON map to reload a session. Click the Import Map (restore a previous session) link to expand the import field, paste the JSON, then click Import.
  • Clear Redaction Map: erases all redactions from memory and clears all input fields. Custom patterns are kept. This cannot be undone.

WHAT REDACTOR DETECTS

What Redactor detects (as of 2 July 2026)

Redactor recognises the following data types automatically:

  • Payment cards: American Express (CM11, CM13, CM15), Visa (13 and 16 digit), Mastercard (Classic 51–55 and New 2221–2720), Discover (6011, 644–649, 65xx), JCB (3528–3589), Diners Club (300–305, 36, 38), UnionPay (62, 16–19 digits). Compact and grouped formats with spaces or hyphens.
  • Cryptocurrency addresses: Bitcoin (legacy, P2SH, bech32/segwit), Ethereum and every EVM chain (0x…), Monero, Litecoin, Tron, Ripple. Structural matching only — checksums are not verified.
  • CF: Italian Codice Fiscale (16-character alphanumeric).
  • National identity / social security numbers: US SSN (dashed form), UK National Insurance number (compact and spaced), Spain DNI/NIE, France NIR (compact and INSEE-spaced), Switzerland AVS (756…), Romania CNP, Finland HETU, Nordic personal numbers (SE/DK/NO, 6-digit date + hyphen + 4 digits), Czech/Slovak rodné číslo (with slash), Belgium national number (dotted form). Digit-only IDs without a distinctive structure (NL BSN, DE Steuer-ID, PL PESEL, HR OIB, UK NHS) cannot be told apart from generic numbers: use a custom pattern if you need them.
  • EMAIL: standard RFC-compliant email addresses.
  • IBAN: bank account numbers — compact, spaced or hyphen-separated, upper or lower case.
  • PHONE_IT_MOBILE: Italian mobile numbers (32x–39x prefixes), with or without +39/0039 country code, compact and grouped formats.
  • PHONE_DE_MOBILE: German mobile numbers (015x/016x/017x prefixes, 7–8 further digits), with or without +49/0049 country code.
  • PHONE_FR_MOBILE: French mobile numbers (06/07 + 8 digits in pairs, dots, hyphens or compact), with or without +33/0033 country code.
  • PHONE_UK_MOBILE: UK mobile numbers (07xxx xxxxxx), compact or spaced, with or without +44/0044 country code.
  • PHONE_INTL: any other international number with an explicit country prefix: +CC followed by 6–12 digits (compact or separated), or 00CC followed by a separator. The compact 00CC… form without separators is deliberately not matched — it cannot be told apart from zero-padded numeric IDs; use a custom pattern if you need it.
  • PCN: prescription control numbers and similar codes of 17 or more consecutive digits.
  • SE10: 10-digit merchant codes. Also catches Montenegro PIB and Turkey VKN by overlap.
  • VAT and fiscal codes for 30+ countries: IT, DE, FR, ES, GB, NL, BE, AT, PT, PL, HR, SI, CY, GR, MT, AL, SE, DK, FI, LU, IE, CZ, HU, RO, BG, EE, LT, LV, SK, US-EIN.

Detection runs in priority order. When two patterns overlap, the longer match wins and the shorter one is discarded.
